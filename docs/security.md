# Security

This page lists the mechanisms for the phone-to-Mac connection and the status of each. The gateway listens on `127.0.0.1` ([ADR 0006](decisions/0006-gateway-binds-loopback-until-pairing.md)), so nothing on the LAN can reach it with the default settings.

## Threat model in one paragraph

The phone and the Mac share a local network that other people may also use, such as an office or a hotel. Recordings and transcripts can contain confidential customer information. An attacker on the same network must not be able to read jobs, submit jobs, or impersonate either device. The user's own devices are trusted once they are paired.

## Planned mechanisms

| Mechanism | Purpose | Status |
| --- | --- | --- |
| mDNS discovery | The phone finds the gateway on the LAN without the user typing an IP address. Discovery only finds the gateway. It grants no access. | not yet implemented |
| Explicit pairing | The user starts pairing on the Mac (`fieldnote-gateway pair`) and enters the code on the phone. Nothing is trusted before that. | implemented on the gateway ([ADR 0009](decisions/0009-pairing-and-sessions.md)); phone side not yet |
| Cryptographically random pairing tokens | A one-time code, shown on the Mac and entered on the phone, generated by a cryptographically secure random number generator. It is single-use and expires after 5 minutes. Repeated wrong codes get 429. | implemented on the gateway |
| Short-lived session credentials | The phone trades its device secret for a 15-minute session token. Job requests carry only the session token. | implemented on the gateway |
| TLS with certificate pinning set at pairing | All traffic uses TLS. The phone records the gateway's certificate fingerprint during pairing and rejects any other certificate afterwards. No certificate authority is involved. | not yet implemented |
| Revocation | `fieldnote-gateway revoke <deviceId>` on the Mac. The gateway rejects the device's sessions and secret immediately. Unpairing from the phone is not yet implemented. | implemented on the gateway |

## Already in place

- The gateway validates its environment at startup and exits if a value is invalid.
- The gateway accepts a caller's `x-request-id` only if it matches `^[A-Za-z0-9._-]{1,64}$`, so an attacker can't inject arbitrary text into the logs through that header.
- No recording or transcript leaves the phone today, because no code sends one.
- The gateway stores only SHA-256 hashes of pairing codes, device secrets and session tokens.
- A device can read only its own jobs. Another device's job ID answers 404.
